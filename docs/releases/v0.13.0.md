# Agent Harness v0.13.0

Agent Harness `0.13.0` adds one entry for an accepted Goal or Milestone.
An immutable two-level plan becomes a real Run DAG. The controller reviews
candidate receipts and fresh verification, then releases only the next eligible
work until the selected target is done.

## Highlights

- Add Goal and Milestone execution plans, dependency-gated manifest v2 Runs,
  and target-scoped next actions.
- Require controller review of candidate receipts, current verification inputs,
  logs, and accepted dependency evidence before a planned node releases its
  successors.
- Share completion checks and synchronize Goal, index, status, Run, and
  checkpoint state through project locks, atomic writes, and recoverable
  synchronization journals.
- Keep manifest v1 Runs and direct or postflight execution. Continuous
  execution and interruption wakeups stay with the host. This release adds no
  scheduler.
- Add planned-execution integration coverage and an opt-in live development
  evaluator with independent code oracles and host provenance.
- Allow an explicit official plugin-validator path. A missing validator is an
  environment error. `npm run validate:plugin:local` is a separate portable
  integrity check.
- Add a Grok host capability and result-packet map. Grok has no runtime
  outcome; `todo_write` is the transient plan, and `spawn_subagent` is
  delegation and worktree isolation.
- Add `.grok-plugin/marketplace.json` so Grok can install the existing plugin
  without changing the Codex marketplace.

## Compatibility Contract

- Existing unplanned manifest v1 Runs stay on their legacy path.
- `host-direct`, `host-direct-postflight`, and `durable-harness` remain the
  three execution paths.
- Native runtime Goals and worker delegation require host support and
  authorization. Foreground execution is the fallback.
- A completed plan node does not complete the Goal or Milestone.
- The controller asks only for a real authority or direction decision.

## Delivery Notes

This release does not add plugin hooks, daemons, watchers, telemetry, paid
services, production access, or a separate marketing website. Agent Harness
remains an adapter-driven control plane for inspectable coding-agent work.
