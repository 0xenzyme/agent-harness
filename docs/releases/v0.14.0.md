# Agent Harness v0.14.0

Agent Harness `0.14.0` removes the Run/evidence-centered control plane.
Harness now controls accepted Goal/Milestone delivery while the host owns
sessions, resume, workers, terminals and full execution output.

## Highlights

- Replace Run preparation, DAGs, checkpoints and revisioned receipts with
  Goal/Milestone delivery control and concise verification summaries.
- Remove source/log hashes, copied logs, evidence sealing and code-drift
  monitoring. Later source edits never reopen completed targets.
- Require concrete acceptance evidence and actual results for declared checks.
  Milestone completion requires all Goals and whole-target verification.
- Keep old Run/checkpoint configuration readable but ignored. Historical files
  do not drive routing, acceptance, task completion or pruning.
- Preserve configured-root containment, bounded status, task compaction,
  candidate-versus-accepted evidence and direct/postflight paths.

## Compatibility Contract

- `goal complete --verification <summary>` and
  `milestone complete --verification <summary>` update only accepted
  Goal/Milestone, task-index and status records.
- Legacy `inputs` and `exclude` fields in old plans are ignored without
  hashing; new plans omit them.
- Old `run` commands return retirement errors. The host owns session recovery.
- Direct work still needs no Harness artifacts. Postflight updates only
  existing state.
- Explicit tamper-evident auditing is a separate extension, not a default
  completion requirement.

## Verification

- `npm run test:all`
- `npm run test:eval`
- `npm run test:eval:development -- --dry-run --case all`
- `npm run validate:plugin:local`
- `git diff --check`
- Read-only M1.5 Goal check returns `done` after subsequent source edits,
  without source hashing or downstream writes.

The official plugin-validator script is unavailable in this environment.
`npm run validate:plugin` therefore reports an environment error; the separate
portable integrity check passes.
