# Agent Harness v0.12.0

Agent Harness `0.12.0` keeps one model-neutral execution contract. Older
models can use the current session and a short checklist; newer hosts may use
runtime outcome, transient plan, delegation, isolation, and result-packet
capabilities when the host exposes them.

## Highlights

- Added a model-neutral runtime capability profile with a conservative
  baseline and optional native Goal, Plan, subagent, and steering capabilities.
- Fall back to the current session without inventing runtime identifiers or
  repository artifacts for unavailable runtime features.
- Reduced repeated execution-role and native-runtime instructions in generated
  Goals while preserving durable evidence, gate, and state-sync contracts.
- Kept `host-direct`, `host-direct-postflight`, `durable-harness`, and prepared
  enforced Run protections compatible.
- Made `README.md` the canonical English homepage and moved Simplified Chinese
  to `README.zh-CN.md`.
- Restored first-screen version, protocol, and smoke badges; routed the README
  hero to the capability matrix, changelog, release notes, and social preview;
  and led first-use with host prompts before CLI adoption.
- Aligned the social preview with host-neutral positioning, added State Sync
  to the preview flow, and published `docs/assets/github/social-preview.png`.

## Compatibility Contract

- Capabilities are detected from the current host, never inferred from a model
  name.
- Missing capabilities fall back to the current session without imitation
  runtime artifacts.
- Deterministic CLI validation remains responsible for path, manifest, gate,
  evidence, and accepted-state checks.
- Prepared enforced Runs retain repository-level recovery and evidence
  requirements across model and host changes.

## Delivery Notes

This release does not add plugin hooks, daemons, watchers, telemetry, paid
services, production access, or a separate marketing website. Agent Harness
remains an adapter-driven control plane for inspectable coding-agent work.
