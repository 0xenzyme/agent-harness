# Agent Harness v0.11.0

Release preparation started: 2026-09-12

This version has not been published as a Git tag or GitHub Release. Local
docs and version metadata are release-prep evidence until a separately
authorized release step creates the tag.

## Summary

Agent Harness now describes durable project control in host-neutral terms.
Codex remains the first host pack; Cursor has a capability and result-packet
map. Ordinary work uses `host-direct` or `host-direct-postflight`. Durable
Goal/Run artifacts no longer generate a Codex-specific execution section.

## Host-Neutral Protocol

- Canonical execution paths are `host-direct`, `host-direct-postflight`, and
  `durable-harness`. Legacy `codex-direct` names remain readable aliases.
- Repository Goal stays the Git-authoritative work unit. Runtime outcome and
  transient plan are host session capabilities, not Codex-only tools.
- `create_goal`, `update_plan`, Thread, and `startingState` live only in
  `plugins/agent-harness/hosts/codex/execution.md`.
- Conversation routes are `current-session`, `delegated-worker`, and
  `isolated-worktree`, with the previous thread names still accepted.

## Install Surfaces

- Control plane: `node plugins/agent-harness/scripts/agent-harness.mjs`.
- Skill discovery: `skills install` copies the four public skills to
  `.agents/skills/` and protocol references to `.agents/references/`.
- Codex marketplace install remains an optional appendix.
- `npm run validate:plugin` validates the Codex pack. Core protocol checks
  use `npm run test:all`.

## Compatibility

- Newly generated Goals write `## Host Execution`. Existing
  `## Codex-Native Execution` sections remain readable.
- Protocol tests no longer require Codex tool names. Codex host checks live
  in `npm run test:hosts-codex`.
- This version does not claim complete multi-agent support. A second host
  still needs an end-to-end `host-direct` / `host-direct-postflight` /
  `durable-harness` walk with inspectable result packets.
