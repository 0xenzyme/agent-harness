# Completion Evidence

Evidence serves the delivered result. Record only what helps the next person
understand acceptance: changed files, actual commands/results or manual review,
uncovered risks and remaining work.

The host session, terminal and CI retain execution detail. Harness does not
duplicate transcripts, copy logs, hash source files, seal receipts or monitor
later edits. A source change never reopens a completed Goal or invalidates its
record. Verify the new change independently when needed.

Task/Goal owns accepted completion. Milestone completion additionally checks
whole-target constraints and integration. Status is a bounded current
projection, not a history log. Postflight updates modify existing records only.

Explicit tamper-evident audit is outside the core contract and must be requested
separately. Ordinary software delivery never requires it.
